# Архитектура

C#/.NET 10 LTS, WPF, MVVM, Microsoft DI и Logging. WPF выбран для Windows-only продукта: штатные диалоги папок, Windows registry, надёжная self-contained упаковка и воспроизводимый render smoke без дополнительных UI-native библиотек. Длительные операции используют async/await, cancellation и потоки файлов; выбор языка отделён настройкой, текст сейчас русский. Полная ресурсная локализация английского ещё не поставляется.

Core содержит модели и интерфейсы. Infrastructure: пути, атомарный JSON, Steam VDF/Epic JSON, обнаружение игры, HTTP download, безопасный ZIP и запуск процессов. Nitrox: immutable release adapter 1.8.1.0, runtime, установка/rollback, конфигурация, миры, backup, IPC, жизненный цикл сервера, запуск игры, обновления. Network: LiteNetLib 1.2.0 handshake, LAN discovery, stateless invites, Tailscale status и локальная диагностика. Diagnostics: JSON-правила, repair и redaction. App: WPF view, MainViewModel, DI, уведомления и подтверждения. Bridge: отдельный процесс, загружающий публичный API неизменённой официальной Nitrox.Launcher.dll.

`NitroxEntryPatch.Apply/Remove`, `NitroxPatcher.dll`, параметры `--nitrox`/`--data-path`, JSON `nitrox.cfg`, текст `server.cfg`, `servers` и length-prefixed IPC проверены по исходникам/реальному архиву 1.8.1.0. Path игры дополнительно задаётся `PreferredGamePath` и `SUBNAUTICA_INSTALLATION_PATH`: это избегает зависимости от выбора установки автоматическим поиском upstream. Steam запускается через `steam.exe -applaunch 264710`, аргументы передаются через ArgumentList. Обновлённый API не угадывается: неизвестный релиз заблокирован до проверки адаптера. Bridge применяет также официальный `PirateDetection.TriggerOnDirectory`; ограничения DRM не обходятся.

Готовность требует upstream `Server started (` и localhost LiteNetLib handshake с ключом `nitrox`. Факт существования процесса недостаточен. Число игроков поступает из `__PLAYER_COUNT__`. `stop` — штатная команда сохранения/остановки; насильственное завершение серверного процесса не применяется. При ошибке запуска остаётся возможность безопасной остановки. Открытый UI предотвращает случайное закрытие и предлагает остановить сервер. Persisted PID/start time дают ограниченную возможность повторного подключения к IPC после аварии лаунчера; reconnect upstream IPC после разрыва не подтверждён отдельным реальным тестом.

Установка: HTTP Range + итоговая hash/size проверка → защищённая ZIP extraction в sibling staging → обязательные файлы → SHA-256 каждого файла → journal → rename старой версии → rename staging → повторная проверка → atomic installation.json. При прерывании журнал восстанавливает прежний каталог; предыдущие/failed/stage каталоги сохраняются для диагностики. Неполные загрузки остаются в cache. Автоматической очистки неопознанных данных нет. NTFS может временно блокировать runtime-файлы во время проверки Defender: directory rename повторяется с ограниченным ожиданием.

Миры идентифицируются GUID, имя — только отображаемый текст. Backup требует остановки сервера, manifest с hash каждого файла; восстановление создаёт новый GUID. Импорт допускает пять основных JSON-файлов и точно совпадающий Version.json, фильтрует executable hooks, не импортирует одиночные сохранения. Переход 1.8.0.1→1.8.1.0 разрешён после backup через upstream save-upgrade и обновление метаданных; других миграций нет.

Собственный update manifest: base64 payload `{Version,Url,Sha256,Size}` и RSA-PSS/SHA-256 signature. Клиент принимает HTTPS, проверяет закреплённый PEM-key, checksum установщика и выполняет уже подготовленный installer после подтверждения. Endpoint/ключ публикации не выдумываются. В настройках есть поля оператора `LauncherUpdateManifest`, `LauncherUpdatePublicKey`; UI конечного пользователя не предлагает неопубликованный update.

В тестах существуют явные fixture seam: отдельный TestServer и SmokeDiscovery. Они применяются только тестами/`--ui-smoke`, отчёты отмечают fixtures. Обычные пользовательские действия никогда не используют mock-успех.
